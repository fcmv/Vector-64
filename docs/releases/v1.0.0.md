# v1.0.0 release guide

This guide covers the published release at commit
`b301d4fea0faf08fa2cf774438b532b027503fd7`, tagged 2026-09-24.
Download from [v1.0.0 assets](https://github.com/fcmv/Vector-64/releases/tag/v1.0.0).

Choose Linux x86-64-v2/v3, Linux ARM64/ARM64-dotprod, macOS ARM64, or Windows
AVX2 according to the CPU and operating system. Windows requires AVX2; Linux
v3 requires the full x86-64-v3 baseline including BMI2. ISA suitability does
not establish a minimum Linux runtime/library version.

Suffixes select classical (none), embedded standard NNUE (`-nnue`), NNUE plus
classical drop variants (`-all`), variants without embedded weights
(`-variants`), non-search validator (`-validator`), and visualizer (`-viz`).
On Windows `.exe` follows the suffix.

## First search

Start the selected NNUE binary. Send `uci`, wait for `uciok`, send `isready`,
then wait for `readyok`. Enter:

```text
setoption name Threads value 1
setoption name Hash value 64
ucinewgame
position startpos moves e2e4 e7e5
go depth 6
```

Wait for `bestmove` before sending `quit`. A UCI chess GUI manages this exchange
for you. The exact best move and scores are not compatibility promises.

The embedded H=1024 network is identified in the
[model card](../model-card.md). The published Windows NNUE executable is the
fixed [architecture baseline](../vector64-spec.md); these docs do not propose
a new feature set or topology. Drop variants use classical evaluation.

## Native visualizer

Launch the release's `-viz` binary with `--headless` to serve the embedded UI
at `http://127.0.0.1:7777`. It is a local, unauthenticated tool. Current
[illustrated UI docs](../visualizer-tour.md) explain the core display; captures
are identified by their checkout and may show later UI fixes.

## Differences from current source

`--perft-divide` and the current shared training/benchmark scripts were added
after this tag. Build current source to use those examples. The original
tagged tree is not a current training environment or a proof of model provenance.

Assets are bare executables. A future release must add the complete applicable
notices, checksums and toolchain/source identity described in
[releasing](../releasing.md). The known Windows `-nnue.exe` SHA256 is
`a71393ffb82c26ac3026b7d9d821de3d74230ef533529d9d582fb6067adf4596`;
this is not a checksum manifest for every asset.
